- **`exec` no longer delivers a credential on stderr or in a failed command's output (#1036)**: stderr was inherited, so it reached the caller without passing through Contexere, and a failed command's stdout was written as it came. Both are now redacted in place, with the notice on stderr. stderr is captured only when stdin is not a terminal, so a prompt still reaches a person; it is capped at 16 MB, and `exec` waits at most two seconds after the command exits for a background process still holding stderr, naming what it did not read. Nothing else changes: failed output is still never distilled, the exit code is the child's, and a person at a terminal still sees output live.
