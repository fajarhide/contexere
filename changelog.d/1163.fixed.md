- **`doctor` and `init --hermes` after the `OMNI_*` names went (#1163)**: #1161 moved every setting to `CONTEXERE_*`, and two places still depended on the old names. The `doctor` probe runs the hook command a host saved, which can still be an `omni` release that reads only `OMNI_DB_PATH` and `OMNI_TRANSCRIPT_DIR`; the probe set only the new pair, so its canary row went into the user's real store. It now sets both pairs on the child, and `the_probe_gets_its_own_database` fails on `OMNI_DB_PATH` with the old pair removed. `contexere init --hermes` skipped an MCP entry it had already registered, so an entry written before 0.9.0 kept `OMNI_AGENT_ID`, which nothing reads, and Hermes calls were booked under the default agent. Init now renames that key inside our `omni` entry under `mcp_servers:`, or drops it when the entry already has `CONTEXERE_AGENT_ID`, since one YAML map cannot hold a key twice. Other servers, YAML comments and CRLF line endings are left as they were; one test each covers a second server that already uses the new name, comments on the section and entry lines, and a CRLF config, and each goes red against the first version of the fix.
