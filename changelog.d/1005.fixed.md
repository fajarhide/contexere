- **Each agent loads its own session in this project (#1005)**: hooks and the MCP server loaded the newest session of any project, so with several agents one could read and overwrite another's state. They now load the session this agent last used in this project, or start a new one. The pipe and `exec` still load the newest session, since they record no agent identity yet. A test with a session saved for another project, and one for another agent in the same project, gets neither back, and went red with the old lookup; post-hook p50 measured 12.8 and 14.2 ms against main's 12.0 and 13.2 ms. The MCP server records its session the same way, so loop settings survive a restart.
