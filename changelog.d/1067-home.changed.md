- **`omni.db` becomes `contexere.db`, and `~/.omni` is no longer left as a link (#1067)**: 0.8.6 moved `~/.omni` to `~/.contexere` and left a link at the old path so an `omni` release still found the data, and kept reading `omni.db` under its old name. The first run of 0.9.0 renames `omni.db` to `contexere.db`, moving the `-wal` and `-shm` files first, since a database opened without its WAL loses every transaction not yet checkpointed. An install that skipped 0.8.6 still has its `~/.omni` moved in one rename, now without the link, and an `omni` directory under `XDG_CONFIG_HOME` or `XDG_DATA_HOME` moves to `contexere` the same way. The link an earlier release left is not moved over the tree it points at. When a rename cannot happen, the data is read where it is rather than shown as an empty store. `contexere reset` names the database it would wipe instead of a fixed `~/.omni/omni.db`. An `omni` release run after this finds no data, so going back to one starts from an empty store.
