- **Every host prunes the database (#1004)**: pruning ran only at session start, which only Claude Code and Codex fire, so the database on other hosts, MCP-only hosts included, grew without bound. It also ran on a thread the hook process did not wait for, so it could stop part way. The post-hook, session start and the MCP server now check once a day, with a read, whether a prune is due, and hand it to a detached `omni --upkeep` process so no hook waits on it. One caller wins the claim. A run that dies part way is retried an hour later, and only a finished run moves the next one a day out. Tests cover the daily cycle, the abandoned claim, and 16 parallel callers on one database, of which exactly one prunes.
